# Weekly Goals and Run Types Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace weekly availability with weekly goals (running distance, long runs, fast runs, strength sessions), give every run an automatic, editable run type, and show what is left of the week on the dashboard and to the coach.

**Architecture:** A `weekly_goals` table (one row per athlete) in the `athlete` module, two new `activities` columns (`run_type`, `run_type_manual`) set by the `training` import paths through a pure `classifyRun` helper, and a pure `computeWeeklyGoalProgress` in `_bff/core` shared by the dashboard card and the coach context. Availability is removed last, in its own migration, so every commit stays green.

**Tech Stack:** Next.js (app router), tRPC, Effect v4, Supabase (`roxcoach` schema), zod, react-hook-form, shadcn on base-ui, TanStack Query, vite-plus tests, PGlite for `db/tests`.

**Spec:** `docs/tech-specs/2026-11-27-weekly-goals-design.md`

## Global Constraints

- Read `CLAUDE.md` before starting. Every rule there applies: `@/` imports only, types at the top of the file, `type Props`, `cn()`, semantic tokens, no em-dashes anywhere, English code and copy, `data-testid` on every element a test uses and tests locate by test id only, no comments that restate the code.
- Never run vitest directly: `pnpm test` (a file filter is fine: `pnpm test weekly-goals`). Before each commit: `pnpm fmt`, `pnpm check`, `pnpm knip`, `pnpm test`.
- Every migration: one transaction, ends with the `schema_migrations` insert, RLS policies in the `(select auth.uid())` / `(select roxcoach.has_access())` form of `0023`. Run `pnpm db:types` in the same commit.
- Table names through `DbTables`, every column list through `selectColumns(DbTables.X, [...])`.
- Repositories: first params `supabase`, `userId`; every query filters by `user_id`, every insert sets it; check both the `tryPromise` catch and the returned `error`; errors carry only `code: message` of a returned error.
- Run type rule defaults: short run under 3000 m, long run over 6000 m, fast pace under 300 s/km. Limits: `0 < shortRunMaxM < longRunMinM <= 100000`, `fastPaceSPerKm` 120 to 600, `weeklyRunDistanceM` 1000 to 500000, long and fast runs per week 1 to 7, strength sessions per week 1 to 14.
- Only `category = 'run'` activities get a run type and count toward running goals. Weeks run Monday to Sunday.
- UI labels: **Long run**, **Fast run**, **None**. Settings tab label: **Goals**. Dashboard card title: **This week's goals**.
- Update the module's tech spec in the same commit as the behavior change (named in each task).

## Review Focus

1. A run with distance but no moving time (manual or indoor files): falls back to elapsed time; a run with neither gets no type. Test in Task 2.
2. A run edited by hand, then the athlete changes the thresholds: the manual type survives the reclassify. Test in Task 5.
3. An athlete who never saved goals: every reader (upload, Zepp sync, coach, dashboard, Settings) gets the defaults and no error. Tests in Tasks 3, 4 and 9.
4. Goals form with a decimal km ("12.5") and a pace typed as "4:45" or garbage ("4:75", "abc"): converts or shows a field error, never sends a bad value. Test in Task 8.
5. An activity from last Sunday or next Monday next to this week's runs: not counted in this week's progress. Test in Task 6.
