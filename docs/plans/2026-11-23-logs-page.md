# Logs Page and Persistent Logs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist every server error and the sync info events in the shared `public.logs` table (new `project` column) and add a `/logs` page in the Soft Studio design to read them.

**Architecture:** The existing `Logger` also inserts a row (service-role client on the `public` schema, `project = 'roxcoach'`); an awaitable `persistLog` serves Trigger.dev tasks. New capture points: the sync tasks, the sync start and finish services, and Next's `onRequestError`. A new `logs` module exposes `logs.getAll`; the page ports the personal-wallet explorer (filters, histogram, table, detail) with this app's components.

**Tech Stack:** Next.js (read `node_modules/next/dist/docs` before touching `instrumentation`), tRPC, Effect v4, Supabase, nuqs, recharts, vite-plus tests.

**Spec:** `docs/tech-specs/2026-11-23-logs-page-design.md`. Behavioral reference for the UI and helpers: `/Users/miguel/Desktop/work/personal-wallet/src/modules/logs/*` and `/Users/miguel/Desktop/work/personal-wallet/src/_bff/modules/logs/*` (read only; restyle, do not copy imports or tokens).

## Global Constraints

- English everywhere, no em-dashes anywhere; `@/` imports only; types at the top of the file; named `type Props`; semantic tokens only; no narrating or JSX comments; `cn()` for classes.
- `public.logs` is the only `public` table allowed, reached only with the service-role client on `db: { schema: 'public' }`, by the logger and the logs repository only.
- Persisted rows: `project: 'roxcoach'`; level `log` is stored as `debug`; rows are written only when `NODE_ENV === 'production'` (added to `src/env/server.ts`).
- Redaction: persisted `metadata` and `error` go through the logger's existing serializer; keys containing `password`, `token`, `apikey`, `secret`, `authorization`, `cookie` become `[redacted]`.
- Persisting never throws and never delays a response. Tasks await `persistLog`; request code uses `Logger` (fire and forget, `after()` inside a request scope).
- Reads always filter `project = 'roxcoach'`; limit 1000 rows (`LOGS_FETCH_LIMIT`); ranges `30m`, `1h`, `24h`, `7d`, `30d`; search max 200 chars; not cached.
- Visibility: every signed-in Roxcoach user sees every Roxcoach row (null `user_id` included). This exception to "filter by `user_id`" is documented in `database.md`.
- Level tones: `error` red, `warn` amber, `info` blue, `debug` slate (`-soft` fill, `-deep` text). Dialogs and drawers only through shared `src/components/ui` components.
- Tests: `pnpm test` only; fake dependencies, no module mocks; locate by `data-testid` only. Each commit passes `pnpm fmt`, `pnpm check`, `pnpm knip`. Nothing is pushed.

## Review Focus

1. **A failing insert never breaks the caller:** a rejecting or throwing insert, and a disabled gate, leave `Logger` and `persistLog` silent. Pinned in Task 2.
2. **Secrets in persisted rows:** metadata `{ apiKey }` and an error carrying `token` are stored as `[redacted]`. Pinned in Task 2.
3. **Search injection:** a search containing `%`, `_`, `,`, `"` and `)` matches literally and cannot add filters. Pinned in Task 5.
4. **Another app's rows:** the query always carries `project = 'roxcoach'`. Pinned in Task 5.
5. **Truncation and empty states:** exactly 1000 rows reports `isTruncated`, zero rows shows the empty state and a filter that matches nothing shows "clear filters". Pinned in Tasks 5 and 7.
6. **A retried or failed task logs once per attempt with the right level, and a successful sync logs exactly one info row.** Pinned in Tasks 3 and 4.
